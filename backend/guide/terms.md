# Academic Sessions

**Where:** Academic Sessions in the menu (`/terms`). **Who:** Super Admin.

Sessions and semesters, which one is current, and the times nothing can be scheduled.

<a id="terms-add-session"></a>
## Add a session

Choose a session, for example 2026/2027, and click **Add Session**.

<a id="terms-session"></a>
## Sessions

Each session is listed with its semesters. Click a session to open it. Only the **current** session can have semesters added and timetables edited; others are view only.

<a id="terms-set-session"></a>
### Set as current session

Makes this session the current one, for everyone in the programme.

<a id="terms-set-semester"></a>
### Set a semester as current

Inside the current session: makes this semester current, for everyone. Its timetables become the ones that can be edited.

<a id="terms-add-semester"></a>
### Add a semester

Add one of the programme's semesters (for example First Semester) to the current session. The names come from the programme's calendar settings. When all are added, you'll see "All semesters added".

<a id="terms-add-blocked"></a>
## Add a blocked slot

Block out time in the current semester so nothing can be scheduled then, for example a public holiday, matriculation or a weekly free period. The form asks for:

- a **name**, shown on the grid;
- what it **applies to:** the lecture timetable, the exam timetable, or both;
- **when:** for lectures, a weekday every week. For exams, one date, or a weekday every week of the exams;
- **start and end time**, or leave them empty to block the whole day. A whole-day block on a date works as a holiday, and it's also used by [Shift exams](timetable-exams.md#tt-shift) and the activity report's out-of-hours check.

<a id="terms-blocked"></a>
## Blocked slots

The current semester's blocked times. **Edit** changes one; **Delete** removes it after you confirm. Items already in the timetable at a newly blocked time aren't moved, but new bookings there are refused.
